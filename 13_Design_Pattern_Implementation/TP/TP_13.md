## Jawaban

### Chain of Responsibility
adalah behavioral design pattern yang memungkinkan sebuah request dilewatkan melalui sebuah rantai handler. Saat menerima request, setiap handler akan memutuskan apakah akan memproses request tersebut, menghentikannya, atau meneruskannya ke handler berikutnya di dalam rantai.

Pada kode di atas, desain ini bekerja dengan cara berikut:
1. Pemisahan Tanggung Jawab: Controller (`controller.createTask`) tidak perlu memusingkan urusan memvalidasi data mentah yang masuk. Tanggung jawab validasi diserahkan sepenuhnya kepada handler sebelumnya di dalam rantai, yaitu fungsi `validate(schema)`.
2. Pemutusan Rantai: Ketika request masuk ke `router.post('/')`, request tersebut pertama kali ditangkap oleh middleware `validate`. Middleware ini mengecek apakah struktur `req.body` sesuai dengan aturan Zod schema (`createTaskSchema`). Jika data tidak valid (`!result.success`), middleware mengambil otoritas penuh untuk memutus rantai saat itu juga dan mengembalikan response error 400 menggunakan `fail(...)`. Request tidak akan pernah mencapai controller.
3. Penerusan Rantai: Jika validasi sukses, middleware akan memperbarui `req.body` dengan data yang sudah di-parse secara aman, lalu memanggil fungsi `next()`. Pemanggilan `next()` inilah yang menjadi inti dari Chain of Responsibility di Express; ia memberi sinyal kepada sistem untuk meneruskan request tersebut ke handler berikutnya di rantai tersebut, yaitu `controller.createTask`.

Desain ini membuat kode menjadi sangat modular. Bisa menggunakan fungsi validate yang sama secara berulang-ulang di berbagai route hanya dengan inject schema Zod yang berbeda-beda tanpa harus menulis ulang logika validasi di dalam setiap controller.
